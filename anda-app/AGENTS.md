# Anda App Agent Handbook

## Purpose
- **Goal**: Ship a desktop client (Tauri + Svelte) for interacting with Anda agents, managing memory capsules, and bridging MCP/tool workflows.
- **Backends**: Talks to `anda_engine_server`, `anda_cloud` canisters, and local MCP tools exposed by Forge/Codex.
- **Platforms**: macOS, Windows, Linux; Tauri bundles Rust backend with the Svelte UI.

## Project Structure
| Path | Description | Notes |
| --- | --- | --- |
| `src/` | SvelteKit components, routes, stores, Tailwind styles | UI/UX lives here; keep state management centralized |
| `src/lib/` | Shared UI modules (layout, helpers) | Mirror backend contracts (e.g., conversation DTOs) |
| `src-tauri/src/` | Rust commands exposed to the front-end | Use `tauri::command`, call into HTTP/MCP clients |
| `src-tauri/src/service/` | Service layer for talking to Anda engine/cloud APIs | Wraps Reqwest, handles auth tokens |
| `src-tauri/src/model/` | Domain structs mirroring Anda DTOs | Keep in sync with `anda_core` types |
| `src-tauri/kip/` | Bundled KIP capsules for bootstrap | Sourced from `KIP/` repo; update alongside spec changes |
| `src-tauri/capabilities/` | Tauri capability descriptors (FS, shell, etc.) | Constrain privileged APIs |
| `src-tauri/locales/` | i18n bundles | Ensure EN/ZH parity |
| `static/` | App icons, default prompts, theme assets | Shared by frontend and installer |

## Data Flow
1. **UI Event** triggers a Tauri command (`invoke`) that maps to a Rust function.
2. **Rust backend** loads configuration (engine endpoints, tokens) and hits either local HTTP server or ICP canister via generated declarations.
3. **Responses** are transformed into front-end-friendly DTOs and returned to Svelte for rendering.
4. **Memory operations** (capsule install, KIP execution) use the `FunctionDefinition.json` schema and capsules from `src-tauri/kip`.

## Development Workflow
- **Install dependencies**
  ```bash
  pnpm install
  pnpm tauri deps install
  ```
- **Run in dev mode**
  ```bash
  pnpm tauri dev
  ```
- **Check types & lint**
  ```bash
  pnpm lint
  pnpm check
  pnpm test
  ```
- **Build release artifact**
  ```bash
  pnpm tauri build
  ```

## Coding Guidelines
- Use Svelte stores for cross-component state; reset when switching agents/workspaces.
- Keep API layer (`src/lib/api`) thin and redirect complex logic to Tauri commands to reuse Rust domain types.
- Maintain parity between Rust models and TypeScript types (consider generating TS types from Rust using `typeshare` if divergence increases).
- Localize user-facing strings; default to English in code, map via locale files.
- Secure secrets: never embed API keys in front-end bundles; rely on user-provided config stored via Tauri secure storage.

## Integration Touchpoints
- **Anda Engine Server**: Ensure health check endpoints (`/health`, `/agents`) are configurable; update UI when new routes appear.
- **Anda Cloud**: Use `src-tauri/declarations/` (generated by DFX) for canister calls; regenerate when candid files change.
- **Forge/Codex tools**: Provide optional MCP client bridging; align with `FunctionDefinition.json` contract.
- **KIP Capsules**: Keep in sync with `KIP/` repo; add migration logic if file names or versions change.

## Testing Tips
- Mock Anda endpoints using `pnpm mock` (if available) or run engine locally via `anda_engine_server`.
- For capsule flows, load `Genesis.kip` first; verify UI surfaces errors gracefully when order is incorrect.
- Use `pnpm vitest run` for unit tests and `pnpm tauri test` for integration (where supported).

## Release Checklist
1. Sync capsules and FunctionDefinition with upstream (`git submodule` or manual copy).
2. Update version in `package.json` and `src-tauri/tauri.conf.json`.
3. Run `pnpm tauri build` on all target platforms or via CI.
4. Smoke-test login, agent selection, KIP execution before tagging.
